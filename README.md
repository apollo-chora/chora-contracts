# Chora Contracts

> API contract boundary for the Chora platform. **Leaf package** — no internal dependencies.
>
> Aligned with **Architecture Review locked 2026-05-07** + **2026-05-15 consolidation** (§5.1-5.4 + §3).

All Chora services consume contracts from this repo. Contracts come BEFORE implementation per **AP-01 (API-First, Headless Always)** — non-negotiable.

Last audited **2026-10-05** — see `~/.claude/plans/transient-hugging-dewdrop.md` §3.2-3.5 for the 2026-05-23 drift catalogue and §4.2-4.3 for reconciliation actions.


## Codegen

```bash
buf lint                                # validate proto definitions
buf breaking                            # check breaking changes against main
buf generate                            # produce gen/{go,python}/ stubs
./scripts/relocate-flat-services.sh     # post-process: align gen/go to declared option go_package paths +
                                        # backfill __init__.py + rewrite Python imports under
                                        # chora_contracts_gen.* prefix
./scripts/flatten-event-schemas.sh      # produce proto/events-flat/ (Path C, locked
                                        # 2026-05-10). Self-contained per-aggregate
                                        # flattened-schema artifact.
```

`gen/` and `proto/events-flat/` are **committed to git** — services consume the generated Go module and Python package directly against the committed output. CI re-runs buf + protoflatten to assert the committed output matches the proto definitions (`tests/test_events_flat_up_to_date.sh` + `internal/protoflatten/main_test.go`).

Hand-edits to `gen/` and `proto/events-flat/` are rejected.

### Why the proto-flatten step (Path C)

Every canonical event proto under `proto/events/{domain}/{aggregate}.proto` imports `chora.common.v1.EventEnvelope` and `google.protobuf.Timestamp`. The `protoflatten` tool reads the buf-built FileDescriptorSet and emits a parallel SELF-CONTAINED tree at `proto/events-flat/{domain}/{aggregate}.proto` that inlines both types into every per-aggregate file — a flattened-schema artifact, not a broker payload. Source-of-truth at `proto/events/` is unchanged — Go/Python codegen continues from there. The step was introduced for a legacy managed schema registry, which rejected `import` statements (history — the platform now uses NATS JetStream); it is retained broker-neutral.

The subject taxonomy `chora.{domain}.{aggregate}.{event_type}.v{N}` means each (domain, aggregate) tuple maps to exactly one flattened schema in `proto/events-flat/`. Multiple subject event_types share that schema. For schema versioning resilience, field numbers are preserved exactly across the flattening — never renumbered. New event types within `v1` are additive (proto3 default) so old subscribers keep working.

### Why the relocator script

Two structural mismatches require a one-shot post-process after `buf generate`:

1. **7 flat service protos collide in Go.** The protos `agent_executor.proto`, `closure_orchestrator.proto`, `guardrail_service.proto` (now deprecated per ADR-152), `langgraph_orchestrator.proto`, and `model_broker_{router,gateway,classifier}.proto` (now archived per ADR-146) sit flat under `proto/services/` (legacy by-purpose layout). Each declares a DIFFERENT `option go_package`, but `paths=source_relative` collapses them into one `gen/go/services/` directory. Go's "one package per directory" rule rejects that. The script moves each pair into its correct `gen/go/chora/services/{name}/v1/` subdir.
2. **Python imports must scope under a stable namespace.** `protoc-gen-python` emits sibling-relative imports like `from services import agent_executor_pb2`. To avoid polluting the global namespace with `services/`, `events/`, `chora/` top-level packages, the script rewrites those imports to use the `chora_contracts_gen.` prefix and backfills `__init__.py` files at every directory under `gen/python/`.

A bulk proto restructure (move flat protos under `proto/services/{name}/v1/`) would eliminate the relocator long-term. Tracked as M11.9b proto cleanup per `buf.yaml lint.except: PACKAGE_DIRECTORY_MATCH`.

## AP-01 (API-First Design — non-negotiable)

1. Protobuf event payload exists BEFORE event publisher.
2. AsyncAPI doc exists BEFORE event publisher (human-readable companion).
3. OpenAPI spec exists BEFORE FastAPI / Chi routes.
4. gRPC service proto exists BEFORE server / client codegen.
5. GraphQL SDL exists BEFORE Strawberry / gqlgen resolvers.
6. Breaking changes → major version bump (new topic `v{N+1}`, new package, parallel-publish during migration).
7. NEVER add implementation code — this is specs and generated stubs only.

## EventEnvelope (mandatory)

Every event message embeds `chora.common.v1.EventEnvelope` as field 1. The envelope carries `event_id` (UUIDv7), `idempotency_key`, `tenant_id`, `gcid`, `occurred_at`, `published_at`, `traceparent`, `tracestate`, `source_project`, `source_service`, `schema_version`, plus optional `correlation_id` / `causation_id`.

Since chora-contracts v2.0.0 (2026-05-09): `chora_imda_dimension` (field 14, ADR-141 canonical labels) + `imda_lifecycle_stage` (field 15, 4-stage lifecycle classifier `ci_pre_merge` / `pre_deploy` / `runtime` / `post_deploy`) are additive envelope fields for IMDA evidence routing.

Payload fields are domain data only.

## Cross-domain rules

- **Cross-DB queries FORBIDDEN** — domain-to-domain communication via NATS JetStream events ONLY. See [`../.claude/rules/ddd-enforcement.md`](../.claude/rules/ddd-enforcement.md).
- **Cross-domain references**: UUID without FK constraint; validate via NATS JetStream events.
- **Soft delete only** — append-only revisions; pseudonymise + crypto-shred for closure (see `account-closure-saga` skill).
- **GCID opaque UUIDv7** — never embed tenant context.
- **AGID distinct from GCID** — agents CANNOT hold `TenantMembership` (per ADR-132).

## Surface-mapped scope (full-deployment intention)

The full-deployment intention adopts the **C.H.O.R.A. surface-mapped solid/dotted convention**:

| Surface | Domains served | Scope |
|---|---|---|
| **A+** (Aspirational/A-plus) | Content Creation + Content Consumption | SOLID |
| **H+** (Hub+) | Tenancy + Billing + Identity admin + IdP + add-ons + members + marketplace | SOLID |
| **R+** (Rhythm+) | Content Delivery + WBL specialisation | SOLID |
| **C+** (Circle+) | Content Sharing (social) | DOTTED |
| **O+** (Observability+) | Governance + Observability + runtime + A2A admin console | DOTTED |

Within in-scope surfaces, certain sub-features are also deferred (§1.4 locked filter).

## Guardrails — Cloud Model Armor (per ADR-152, supersedes chora-guardrail)

Per **ADR-152** (PROPOSED 2026-05-13 → ACCEPTED 2026-05-14), the `chora-guardrail` Go service is **DECOMMISSIONED**. Cloud Model Armor GA natively composes the 3-tier screening (regex + DLP + LLM filters) that chora-guardrail was orchestrating. LLM-issuing services (Model Broker Gateway successor / ChoraLabeledGemini extension per ADR-146) now call Cloud Model Armor SDK directly pre/post-LLM. Violation events flow through the event bus (envelope shape unchanged).

`proto/services/guardrail_service.proto` is retained on disk for codegen continuity but marked deprecated; will be removed at the next major bump. Archive tag: `archive/chora-guardrail-pre-armor-ga`.
